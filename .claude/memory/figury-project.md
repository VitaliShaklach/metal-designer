## Решения Виталия (не спорить повторно)
- **Термины:** заготовка — плоская до гибки; элемент — она же после гибки; деталь № — грань фигуры; позиции на резку — всё, что режут. «Кусок» в интерфейсе не писать.
- Заготовки — Г1, Г2… (не «З»: на чертеже читается как 3). Зеркальные пары «7 / 7.1» всегда, .1 — правая сторона.
- V — гнуть на себя, m — от себя, глядя на сторону с гравировкой; число — угол между гранями (180 = плоско). Гравировка изнутри. Пропил болгаркой — только по V.
- Пороги гибки: угол ≥135°, ≤7 сгибов в цепи, грань ≥20, ширина ≥20, линия ≤300 мм; линии сгиба на детали не сходятся в вершине.
- Перфорация сгибов: прорези вдоль линии длиной 2 мм, шаг ≤20, центр первой — 10 мм от конца, на V и m, только лазер; метраж отдельной строкой (цена — врезки). «Гравировку толще» не делать.
- DXF: у каждой детали ENGRAVE → BEND_V/BEND_M → PERF → CUT последним.
- Шаг сборки: другая половина фигуры — призраком (stepShown), кадр ≥ 2,5 размера элемента; ракурс — прежний (Виталий выбрал из 4 вариантов 28.10).
- Техтребования «Общего вида» — крупно (4 мм) и широко, до правой рамки.
- Сварка — TIG (аргон) по умолчанию: зазор 0,5; полуавтомат — 1 (лист до 1,5 — 0,5). Под TIG в DXF надпись N2 латиницей на слое SHEET и «_N2» в имени файла. Старые .json без weld — полуавтомат.
- Картинки — 3D-снимки (`pieceShots`, `bendShot`, `stepShot`); схемы `facesSVG` Виталию «непонятны», остались только без WebGL. На снимке сгиба — ГОТОВЫЙ элемент. Без «Уголков» — дуга угла с цифрой (нравится); «Уголки» сами не включать — попадут в раскрой.
- Предлагал и не взял: подпись «№ N — за элементом» для спрятанного соседа; «слить почти плоские грани 12°» (нужно 1 в 1 с эталоном Meshy). Транспортир на картинке и профили «до → после» — отложены.
- Лишние швы, второй круг (28.10): Д10 = Д9 со слитыми щеками (35+28), теменем и лбом (22, 22.1, 27, 27.1 — одна пластина). Оставлены 40–30, 54.1–53.1, 25.1–18.1, 21–21.1 (номера Д9): уже гнутся, излом 5–11°. Каждый круг — новая фигура, старая остаётся в списке (Д9 не трогать).
- Д11 (28.10, v0.19.0) = Д10 со слитыми 31+30 и 31.1+30.1 (плоский шов 180°, заодно ушёл «бантик» 31), `marks/round4.js`. 24–24.1 (178°) не сливали: точки до 1,5 мм, изломы соседей до 1,4°, новый «бантик» 37 — только отдельным кругом с выравниванием соседей.
- Ползунок граней у фигур из плит выключен намеренно: плиты = эталон, уменьшать — «Убрать шов».
- Между деталями на листе — 5 мм по умолчанию (Виталий, 28.10, v0.18.2; было 3). Лазеру хватает 3–5, плазме 6–8.

## Ловушки кода
- Обычные `<script>`, общие глобальные имена, без сборки. Правил ассет — поднять `?v=`, иначе браузер берёт старое из кэша.
- smoke грузит mesh, edit, models, models-poly, figures, prod, sheets, bend — но не view3d: снимки проверять заглушками на `globalThis`.
- Концы строк (проверено 28.10): `bend.js` — CRLF; `CHANGELOG.md`, `smoke.js`, `view3d.js`, `sheets.js` — LF. Перед вставкой через node — `file`.
- Слияние плит (`clean.js` mergeSeam): выравнивание может положить СОСЕДНЮЮ плиту в плоскость с новой (Д10: №26 6,7° → 0,2°) — после слияний сравнивать изломы по рёбрам Д(n) → Д(n+1) и при нужде `solve` с `fix` плоскостей соседей (см. `marks/round3.js`). `bend.js` CLI «плохих контуров N» — сырой план; сайт такие сгибы сам переводит в сварку (`ui.js:30`), считать по «Итого» сайта.
- Длинные однострочники править node-скриптом из scratchpad с точной заменой (не нашлось — ошибка). `//` посреди однострочника ломает код — в ui.js это smoke не ловит (он не грузит ui.js): после правок ui.js — проверка в браузере.
- Номер детали в 3D и на снимках — `partLabelPt(p,M3)` (prod.js, самое просторное место грани), НЕ `p.c`: `p.c` — среднее углов, у вогнутых деталей за контуром. `partHasPt(p,M3,q,m)` — точка на детали с запасом.
- Шов №1 на щеке Д10 (32–41, 5°, 98 мм) оставлен решением Виталия 28.10: слияние двигает точки до 4 мм и изломы вокруг головы до 8°. Без «Гнуть» это сварной шов.
- `SH_STYLE` действует только внутри `svg.shs`. `placeLabels` — общий раскладчик подписей. `itemMarks` кэшируется в `o._mk` (ключ: BL, гравировка, перфорация).
- Раскрой строится в фоне: перед `buildSheets()` вызвать `ensureNest()`.
- `meetLines` убирает только вывернувшуюся СОСЕДНЮЮ сторону; перекрест несоседних сторон («бантик») ловит `untwist` в `cutContour` (v0.18.3). Плиты-«бантики» есть в самих моделях Д7–Д10 (41, 43, 46, 31): вывернутый палец лежит поверх соседней плиты — `p.area` его считает. Проверка DXF целиком — `page-check.js {dxf:true}`.
- Геометрия в 2D: прямая ровно через вершину многоугольника даёт параметр пересечения −1e-17 / 1+ε — сравнения `u>=0&&u<=1` без допуска теряют точку (так линии сгиба торчали за заготовку, `clipSeg`, v0.19.0). Ставить допуск 1e-9.
- Картинку из превью не тащить через base64 в ответ (≈ 20 КБ на кадр — дорого); 3D-место показывать живым в панели или снимать headless Chrome в файл.
- Подложки глаз (`p.back`) не входят в `M3.F` — на снимки добавлять отдельно (`backPts`).
